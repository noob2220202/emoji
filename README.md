# 텔레그램 프리미엄(커스텀) 이모지 팩 봇

사진이나 GIF/영상을 보내거나 문구를 입력하면 자동으로 격자로 잘라 텔레그램 커스텀
이모지 팩(`t.me/addemoji/...`)을 만들어주는 봇입니다.

## 빠른 시작 (git clone → pm2 start)

```bash
git clone <이 저장소 URL>
cd emoji

pip install -r requirements.txt        # 가상환경 없이 시스템에 바로 설치
# (에러 나면: pip install --break-system-packages -r requirements.txt)

cp .env.example .env
# .env를 열어 BOT_TOKEN=... 에 BotFather에서 받은 토큰을 넣는다

npm install -g pm2                     # pm2가 없다면
pm2 start ecosystem.config.js
pm2 logs emoji-bot                     # 정상 기동됐는지 로그 확인
```

각 단계에 대한 자세한 설명은 아래 [설치](#설치), [설정](#설정), [실행](#실행) 항목을 참고하세요.

## 동작 방식

1. **사진/GIF/영상을 보내거나, 만들고 싶은 문구를 그냥 채팅으로 입력**해서 이모지로 만들 원본을
   만듭니다(명령어 없음 — 사진이면 정지 이미지 파이프라인, GIF/영상이면 영상 이모지 파이프라인,
   텍스트면 [글자 이모지화](#글자-이모지화-문구를-그냥-채팅으로-보내면-시작)로 자동 분기됩니다).
2. 봇이 **"🖼 원본 그대로" / "✂️ 배경 제거(누끼) 후"**를 버튼으로 물어봅니다(사진/GIF/영상일 때만).
   배경 제거는 [rembg](https://github.com/danielgatis/rembg)로 처리하고, 영상/GIF는 프레임 단위로
   돌린 뒤 알파 채널을 가진 WEBM으로 다시 인코딩합니다(프레임이 많으면 시간이 좀 걸립니다).
3. **어느 이모지 팩에 넣을지** 물어봅니다: "🆕 새 팩 만들기" 또는 이미 이 봇으로 만든 기존 팩 중
   같은 포맷(정지/영상)이면서 용량이 남은 팩 목록.
   - 새 팩이면 채팅으로 **팩 이름을 입력**해달라고 합니다.
   - 기존 팩이면 텔레그램 서버에 실시간으로 남은 용량을 다시 확인한 뒤 바로 다음 단계로 넘어갑니다.
4. **원하는 조각(이모지) 개수를 숫자로 입력**해달라고 합니다 (권장 6~10개).
   - 원본 가로세로 비율에 맞춰 이 개수에 가장 가까운 정사각형 열x행 조합을 자동 계산합니다
     (정사각형 타일 제약 때문에 요청한 숫자와 정확히 일치하지 않을 수 있고, 이 경우 실제
     계산된 개수를 결제 전에 다시 보여줍니다).
5. **무료 횟수**가 남아있으면(또는 관리자면) 곧바로 **처리 대기열**에 등록되고, 없으면
   **텔레그램 Stars**로 결제를 요청합니다(아래 [요금제](#요금제-균일-가격--stars-결제)와
   [처리 대기열/동시 처리](#처리-대기열-및-동시-처리) 참고).
6. 대기열 순서가 되면 그때 배경 제거/분할/렌더링을 실행하고, `createNewStickerSet`(새 팩)
   또는 `addStickerToSet`(기존 팩, sticker_type=`custom_emoji`)로 정지는 100x100 PNG,
   영상은 100x100 WEBM(VP9, 3초/256KB 이하) 이모지들을 만들어 완성된 팩 링크를 답장으로 보냅니다.

타일은 왼쪽 위부터 순서대로 만들어지므로, 완성된 이모지들을 순서대로(행 우선) 이어 붙이면 원본 그림이 재구성됩니다.

모든 선택 단계(버튼이든 채팅 입력 대기든)에는 **❌ 취소** 버튼이 함께 붙어있어서, 언제든 눌러서
진행 중인 요청을 중단할 수 있습니다(임시 파일도 함께 정리됩니다).

## 글자 이모지화 (문구를 그냥 채팅으로 보내면 시작)

명령어 없이, 이모지로 만들고 싶은 문구를 그냥 채팅으로 보내면 시작됩니다.

```
펭구 화이팅
```

진한 배경 위에 금속(크롬) 느낌 그라데이션을 입힌 글자 이미지를 만든 뒤, 사진과 비슷한 파이프라인
(팩 선택 → 결제/무료 → 제작)을 그대로 탑니다. 순서:

1. **폰트 선택** (버튼): 블랙한산스(임팩트), 주아(귀여움), 도현(심플), 나눔펜(손글씨) — 모두 한글을
   지원하는 무료 구글 폰트(OFL 라이선스)를 받아 `assets/fonts/`에 번들해뒀습니다.
2. **색상 선택** (버튼): ⚪ 실버 / 🟡 골드 / 🔵 블루 / 🔴 레드 / 🟢 그린 / 🟣 퍼플 크롬 — 전부 같은
   금속 그라데이션 기법에 색상만 다르게 입힌 것입니다(테두리 + 세로 그라데이션, Pillow로 직접 합성).
3. **정지 이미지 / 움직이는 GIF 선택** (버튼):
   - 🖼 정지 이미지: 진한 단색 배경 위에 글자를 그린 PNG.
   - 🎬 움직이는 GIF: 글자는 고정한 채 뒤쪽 배경 그라데이션이 좌우로 흐르듯 움직이는 3초짜리
     애니메이션 배너를 만든 뒤(PIL로 프레임을 그려 ffmpeg로 WEBM/VP9 인코딩), 이미지 분할과 같은
     방식으로 각 조각을 움직이는 영상 이모지(WEBM)로 만듭니다.
4. **조각 수를 따로 묻지 않습니다.** 글자 이모지화는 **세로가 항상 이모지 한 칸(1행)으로 고정**되고,
   가로 칸 수는 문구 길이에 맞춰 자동으로 정해집니다(원본 폭을 한 칸도 잘리지 않게 담을 수 있는 만큼).
   문구가 길수록 칸이 늘어나고 짧으면 줄어듭니다 — 사진처럼 원하는 개수를 직접 입력하는 대신, 만들어진
   결과("✅ NxN (K개)로 만들어졌어요!")를 그대로 팩 선택 단계로 넘깁니다.
5. 정지/영상 포맷은 텔레그램 규격상 한 팩에 섞을 수 없어서, 팩 선택 목록도 같은 포맷의 팩만
   후보로 보여줍니다.

새 색상 프리셋을 추가하려면 `bot/text_emoji.py`의 `STYLES` 딕셔너리에 항목을 추가하면 됩니다
(`text_colors`: 글자 그라데이션, `wave_colors`: 움직이는 버전에서 흐르는 배경 색). 세로 1행 고정
로직은 `bot/grid.py`의 `compute_single_row_grid()`에 있습니다.

## 요금제 (균일 가격 + Stars 결제)

- 이모지 팩 제작 1건(사진/GIF/영상/문구, 새 팩이든 기존 팩에 추가든 상관없이): **항상 10 ⭐로 균일**
  (기본값, `.env`의 `STAR_PRICE`로 조정 — 값을 바꾸면 아래 "대기열 우선 처리" 결제 가격도 함께
  바뀝니다. 두 결제는 항상 같은 가격을 씁니다).
- 하루 무료 **2회** (기본값, `.env`의 `FREE_USES_PER_DAY`로 조정), 매일 자정(기본 KST, `QUOTA_TIMEZONE`으로 변경 가능)에 초기화
- 남은 무료 횟수는 화면에 따로 표시하지 않습니다. 다 쓰면 "오늘의 무료 제작 횟수를 모두
  사용하셨습니다. 내일 다시 무료로 이용하실 수 있습니다."라고 안내하고 바로 Stars 결제 UI를 띄웁니다.
- 결제가 완료되면 자동으로 우선 처리 대기열에 등록되고, 만약 처리 중 오류가 나면 결제한 Stars를
  자동으로 환불합니다(`refundStarPayment`).
- Stars 결제는 `provider_token` 없이 `currency="XTR"`로 보내는 텔레그램 기본 기능이라 별도 PG 연동이
  필요 없습니다.
- 가격/무료 횟수는 `.env`의 `STAR_PRICE`, `FREE_USES_PER_DAY`로 조정할 수 있습니다.
- `.env`의 `ADMIN_USER_IDS`(쉼표로 여러 명 구분)에 텔레그램 유저 ID를 넣으면, 그 유저는 무료 횟수
  제한과 Stars 결제 없이 항상 무제한으로 처리되며 대기열에서도 결제 건과 같은 우선순위를 받습니다
  (완성 메시지에 "관리자 계정" 표시). 기본값에 이미 `7648288400`이 들어있습니다.

## 처리 대기열 및 동시 처리

배경 제거/분할/인코딩/팩 생성은 CPU를 많이 쓰는 작업이라, 한 번에 너무 많은 요청이 몰리면 서버가
버벅일 수 있습니다. 그래서 다음과 같이 동작합니다.

- 동시에 최대 **`MAX_CONCURRENT_JOBS`건**(기본 3건, `.env`로 조정)까지만 실제로 처리하고,
  나머지는 순서대로 대기열에서 기다립니다.
- **결제 완료 건과 관리자 건이 항상 우선 처리**되고, 무료로 처리되는 건은 그 다음 순서로 처리됩니다.
  결제 건끼리는 먼저 결제한 순서, 무료 건끼리도 먼저 요청한 순서(FIFO)를 지킵니다.
- 대기가 필요한 경우 "🕒 처리 대기열에 등록되었습니다 · 회원님 앞에 N명이 대기하고 있습니다"라고
  안내하고, 무료로 대기 중인 사용자에게는 **"⭐ 10 Stars 결제하고 우선 처리"** 버튼을 함께 보여줍니다.
  이 버튼으로 결제하면 그 자리에서 대기열의 맨 뒤가 아니라 **우선순위 대기열로 즉시 승격**되어
  대기 없이(또는 다른 결제 건 다음으로) 처리됩니다.
- 슬롯에 바로 여유가 있으면(동시 처리 인원 미만) 대기열 안내 없이 곧바로 제작이 시작됩니다.
- 대기 중에 ❌ 취소를 누르면 대기열에서 빠지고, 뒤에서 기다리던 사람들의 순번이 자동으로 앞당겨집니다.
- 무거운 작업(rembg 배경 제거, ffmpeg 인코딩, Pillow 분할)은 전부 스레드로 넘겨서 처리하므로,
  여러 건이 실제로 동시에(진짜 병렬로) 진행되는 동안에도 다른 사용자의 버튼 클릭이나 메시지 응답이
  막히지 않습니다.

관련 로직은 `bot/handlers.py`의 `_enter_processing_queue()` / `_try_dispatch()` /
`_run_processing()`에 있습니다.

## 이모지 팩 선택 / 이어서 추가하기

텔레그램 Bot API에는 "이 봇이 만든 팩 목록"을 조회하는 방법이 없어서, 봇이 직접 `data/bot.db`
(SQLite, `.gitignore`에 포함되어 커밋되지 않음)에 사용자별로 만든 팩 이름/타일 수를 기억해둡니다.

- 새로 처리할 때마다 "새 팩 만들기" 또는 용량이 남은 기존 팩 중 하나를 선택할 수 있습니다.
- 기존 팩을 고르면 로컬 DB 기록과 별개로 `getStickerSet`으로 실시간 상태(현재 개수)를 한 번 더
  확인해서, 사용자가 텔레그램 앱에서 직접 스티커를 지웠거나 팩이 삭제된 경우에도 안전하게 처리합니다.

## 배경 제거(누끼) 기능

사진을 보내면 봇이 "원본 그대로" / "배경 제거(누끼) 후" 중 하나를 버튼으로 물어봅니다.
배경 제거는 [rembg](https://github.com/danielgatis/rembg)(U^2-Net 기반 오픈소스 배경 제거 라이브러리)를 사용합니다.

- 처음 실행 시 선택한 모델 파일을 자동으로 다운로드합니다(`~/.rembg`에 캐시됨, 인터넷 필요).
- 기본 모델은 빠른 `u2netp`입니다. 정확도가 더 필요하면 `.env`의 `REMBG_MODEL`을 `u2net`이나
  `isnet-general-use` 등으로 바꾸세요(대신 느려집니다).
- 버튼을 누르지 않고 방치된 요청은 15분 후 자동으로 정리됩니다.
- 버튼 자체가 필요 없다면 `.env`의 `OFFER_BACKGROUND_REMOVAL=false`로 끌 수 있습니다(항상 원본 그대로 처리).

## 설치

이 프로젝트는 가상환경 없이 시스템 파이썬에 바로 설치해서 씁니다.

```bash
pip install -r requirements.txt
```

배포판에 따라(Debian/Ubuntu 최신 버전 등) `error: externally-managed-environment` 에러가 날 수 있습니다.
그럴 경우:

```bash
pip install --break-system-packages -r requirements.txt
```

글자 이모지화의 움직이는 GIF 옵션과, 사용자가 직접 올린 GIF/영상을 이모지로 쪼개는 기능은 ffmpeg으로
영상을 인코딩합니다. 시스템에 `ffmpeg`이 설치되어 있으면 그것을 쓰고, 없으면 `imageio-ffmpeg`이
제공하는 내장 바이너리를 자동으로 사용합니다(내장 바이너리도 동작은 하지만, 가능하면 시스템 ffmpeg
설치를 권장합니다: `apt-get install ffmpeg`).

## 설정

`.env.example`을 `.env`로 복사한 뒤 값을 채웁니다.

```bash
cp .env.example .env
```

- `BOT_TOKEN`: [@BotFather](https://t.me/BotFather)에서 `/newbot`으로 발급받은 토큰을 넣습니다.
  **토큰은 절대 커밋하거나 채팅/로그에 노출하지 마세요.**
- 나머지 값은 필요할 때만 조정하면 됩니다 (`.env.example` 주석 참고).

## 실행

### 그냥 실행 (포그라운드)

```bash
python -m bot.main
```

봇에게 `/start`를 보내거나 바로 사진/문구를 전송하면 됩니다. 명령어는 `/start` 하나뿐이고
(텔레그램 클라이언트에서 `/`를 입력하면 뜹니다, `setMyCommands`로 자동 등록), 나머지는 전부
버튼/채팅 입력으로 진행됩니다. 첫 실행 시 `data/bot.db`(SQLite)가 자동으로 생성됩니다.

### pm2로 실행 (백그라운드 + 자동 재시작)

서버에 계속 띄워둘 거라면 [pm2](https://pm2.keymetrics.io/)로 관리하는 걸 추천합니다.

```bash
npm install -g pm2   # pm2가 없다면 먼저 설치 (Node.js/npm 필요)
pm2 start ecosystem.config.js
```

- `ecosystem.config.js`는 저장소에 이미 포함되어 있고, `python3 run.py`를 실행하도록 되어 있습니다
  (`bot/main.py`는 상대 임포트를 쓰기 때문에 `python -m bot.main`처럼 패키지로 실행해야 하는데,
  pm2는 스크립트 파일 경로만 받을 수 있어서 `run.py`라는 얇은 진입점을 따로 뒀습니다).
- `.env` 파일은 `bot/config.py`가 `python-dotenv`로 알아서 읽으므로 pm2 설정에 토큰을 직접 넣을 필요는 없습니다.
  단, `pm2 start`를 실행하는 디렉터리(`cwd`)가 저장소 루트여야 `.env`를 찾습니다.

자주 쓰는 pm2 명령어:

```bash
pm2 status              # 실행 상태 확인
pm2 logs emoji-bot       # 실시간 로그
pm2 restart emoji-bot    # 재시작 (코드나 .env 수정 후)
pm2 stop emoji-bot       # 중지
pm2 delete emoji-bot     # pm2 목록에서 제거
pm2 save                 # 현재 pm2 프로세스 목록 저장
pm2 startup              # OS 재부팅 시 pm2가 자동으로 살아나도록 등록 (출력되는 명령어를 그대로 실행)
```

### 문제 해결: pm2에 online으로 뜨는데 봇이 응답이 없음

`pm2 status`에는 `online`(재시작 횟수 0)으로 나오는데 텔레그램에서 `/start`를 보내도 아무 반응이 없고
로그도 텅 비어있다면, 배경 제거 기능(`rembg`)이 내부적으로 물고 오는 `pymatting`/`numba`가 원인일 수
있습니다. `numba`는 처음 임포트될 때 JIT 컴파일을 시도하는데, CPU 자원이 넉넉하지 않은(다른 프로세스와
공유하는) 서버에서는 이 컴파일이 수십 초~몇 분씩 걸리거나 사실상 멈춘 것처럼 보일 수 있습니다. 이 경우
프로세스는 죽지 않고 계속 "그 임포트 도중"에 멈춰 있는 상태라 pm2는 정상(`online`)이라고 판단하지만,
실제로는 `run_polling()`까지 코드가 도달하지 못해 텔레그램 요청을 전혀 처리하지 못합니다.

이 봇은 `bot/__init__.py`에서 `NUMBA_DISABLE_JIT=1`을 자동으로 설정해서 numba가 컴파일 없이 순수
파이썬으로 즉시 동작하도록 미리 막아뒀습니다(실행 속도 이득은 필요 없는 부분이라 안전합니다). 그래도
같은 증상이 재현된다면:

```bash
pm2 restart emoji-bot
pm2 logs emoji-bot --raw   # 재시작 직후 잠깐 걸린 뒤 정상적으로 응답하는지 확인
```

## 테스트

네트워크나 텔레그램 토큰 없이 실행 가능한 단위 테스트(그리드 계산, 이미지 분할, 글자 이모지 렌더링,
DB 로직)가 있습니다.

```bash
pip install pytest
pytest
```

배경 제거(`bot/background_removal.py`)는 rembg 모델 다운로드(인터넷)가 필요해 단위 테스트에는
포함하지 않았습니다. 글자 이모지화의 움직이는 GIF 관련 테스트는 ffmpeg이 없으면 자동으로
건너뜁니다. 실제로 사진을 보내서 동작을 확인해보세요.

## 알아두면 좋은 제약사항

- 텔레그램 커스텀 이모지는 정지(PNG/WEBP)와 영상(WEBM/VP9) 두 포맷을 지원하며 항상 100x100이어야
  합니다. 이 봇에서 사진(또는 이미지 문서) 업로드는 항상 정지 이미지로 처리되고, GIF/영상을 직접
  올리거나 글자 이모지화에서 "🎬 움직이는 GIF"를 고르면 영상(움직이는) 이모지로 처리됩니다. 영상
  이모지는 최대 3초, 최대 256KB여야 해서 자동으로 잘라내고 용량을 맞춥니다. 텔레그램 규격상 정지와
  영상은 한 팩에 섞을 수 없어서, 기존 팩에 이어서 추가할 때도 포맷이 같은 팩만 후보로 보여줍니다.
- 이모지 팩 하나에 넣을 수 있는 이모지 개수는 텔레그램 자체 한도가 있습니다(`MAX_TILES`로 여유 있게 제한).
- 만들어진 이모지 팩(`custom_emoji`)은 텔레그램 프리미엄 사용자만 실제로 "전송"할 수 있고,
  프리미엄이 아닌 사용자도 보는 것은 가능합니다.
- 텔레그램 Stars는 테스트/샌드박스 모드가 따로 없어서, 유료 결제 흐름을 실제로 테스트하려면 계정에
  진짜 Stars가 있어야 합니다. 무료 횟수(`FREE_USES_PER_DAY`) 안에서는 결제 없이 전체 흐름을 테스트할
  수 있습니다.
- `data/bot.db`는 이 봇 프로세스가 만든 팩만 기억합니다. 서버를 옮기거나 DB 파일을 지우면 "기존 팩에
  추가" 후보 목록에서 사라지지만(텔레그램에는 팩 자체는 그대로 남아있음), 팩 이름을 알면 텔레그램 앱에서
  직접 편집할 수는 있습니다.
- 사용자가 입력한 "원하는 조각 개수"는 정사각형 타일 제약과 원본 비율 때문에 정확히 그 숫자로
  나오지 않을 수 있습니다(가장 가까운 값으로 근사). 실제 결과는 처리 과정에서 안내 메시지로
  다시 보여줍니다.
